# LANES.md — segments, gates, and the seams between them

Four generalists, no fixed owners. The old model (one person = one lane) is retired: **anyone may enter any segment, but one branch works in one segment, and that segment's gate must be green before merge.** You may read anything; you write only inside the segment your branch claims. The human-facing map (bokmål) is `TEAM.md`; this file is the technical contract.

## Interface contracts (the seams between segments)

1. **Engine API** (3 → 2/5/7): `Lab/js/engine.js` exports a pure state machine — `createGame(config)`, `dispatch(state, action) → state`, `selectors.*`. No DOM, no timers, no randomness without an injected `rng`. The SwiftUI `GameEngine` mirrors this shape 1:1. Screens render state; screens never compute scores.
   **Phase timers do not change this.** A deadline is not engine state's business: `clock.js` decides *when*, and hands the engine an ordinary action (`timeoutBluffs`, `timeoutDecoys`, `timeoutVotes`) that is indistinguishable from a player acting. The engine still has no clock, and every timeout rule is provable by a vector with no timing in it.
2. **Tokens** (1 ↔ everyone): `DesignSystem/tokens.json` → generated outputs. Nobody hand-edits generated files; `node Tools/tokens-build.mjs --check` fails the gate on drift.
3. **Deck schema** (4 → 2/3): `Resources/deck_nb.sample.json` is the contract. Schema changes are a `/director` event (rules updates loaders, screens update card views, word lists migrate decks — one commit).
4. **Sound grammar** (4/7 → 2): event names in `tokens.json → sound.grammar` map to files promoted into `Resources/Audio/`. Screens trigger events by name, never by filename.
5. **Pacing constants** (7 + 5): **bot** pacing lives in one frozen block in `Lab/js/bots.js TUNING` (and later `Sources/Engine/BotTuning.swift`); **phase deadlines** live in one frozen block in `Lab/js/clock.js TIMERS`. Two blocks because they answer to different masters — bot delays are feel, deadlines are rules the host sets and every device obeys. Nobody inlines a magic number into either.

Plus two more, from the screens registry and the network:

6. **Fixture mirror** (2): `fxMakeG()` in `Lab/js/fixtures.js` mirrors the `G` literal in `ui.js startGame()` — change one, change both (fixtures.test enforces the keys). Fixture ids are the permanent screen numbers in `Screens/SCREENS.md`.
7. **Transport seam** (5 → 2/3): `Lab/js/net.js` exposes `{isHost, roomCode, send, sendTo, onMessage, onPeerChange, close}` and nothing else. `LoopbackTransport` is local play; `PeerTransport` is online — the rest of the app cannot tell which it is holding. Two rules keep it honest: **only the host advances the game** (clients render what they are told), and **`netProject(G, seat)` is the only way state leaves the host** — it strips the truth, other players' drafts, and live vote attribution before the wire. Screens read `U.lobby`/`U.room`/`U.profile`, never the `NET` singleton, so `fixtures.js` stays importable and DOM-free.

## Working rhythm

- Branch `segment/short-desc` → pull → run that segment's gate → work → run it again → commit with the PRD section or screen number in the message → merge.
- If your change touches another segment's files, stop and run `/director` instead of editing — it stages both sides and runs the gates in one commit.
- Merge conflicts in generated files (`Lab/css/tokens.css`, `Sources/DesignSystem/Theme.swift`, `Specs/SCORING.md`, `dist/`): never resolve by hand — regenerate (`tokens-build`, `rules-sheet`, `build-standalone`).
- `dist/` is tracked: any Lab change ships with a fresh `node Tools/build-standalone.mjs` in the same commit.
- Before main: `/qa`. Before anything leaves the house: `/qa --ship`.
